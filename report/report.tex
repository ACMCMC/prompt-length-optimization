\section{Introduction}
\label{sec:introduction}

% Idea: we're doing prompt optimization for LMs, this has applications in e.g. security research (find jailbreaks) or improving performance (e.g. improving prompts to maximize their effectiveness on downstream tasks)
Language models (LMs) have become popular for many NLP tasks. However, making models follow specific commands well is still hard, especially because instruction-following LMs often behave in unpredictable ways. Prompt optimization tries to solve this by finding a set of tokens that makes the model produce a specific response. This work has uses in security research (finding jailbreaks), improving performance, and task-specific tuning.

% Idea: highlight gap between likelihood-only search and static pruning
While there is much interest in prompt optimization, some challenges remain. In this paper we focus on one aspect that gets overlooked: many search methods only optimize for likelihood and ignore length. Figure~\ref{fig:gcg_length_sweep} shows this clearly: when we run GCG at different suffix lengths, longer suffixes get better likelihood, but GCG never tries to compress. Shorter prompts are usually better in practice because they cost less to run, are faster, and are easier for people to use. Our work tries to balance both goals at once; we want to maximize the likelihood of a target completion while keeping the prompt short.

% Idea: explain our external policy and scope (plug-in optimizer, no retrieval/safety)
We train a small external policy that is separate from the LM (we treat the LM as a black box). The policy decides when to shrink, keep, or grow a prompt; any plug-in optimizer handles the token changes. We don't design a new optimizer, we just use whatever optimizer is given. We also skip retrieval and safety goals, we only care about balancing likelihood and length.

\section{Related Work}
\label{sec:related}

% Idea: prompt optimization is popular, many methods exist
Prompt optimization is an active research area with many different techniques. We group prior work into four areas:

\paragraph{Discrete optimization.} These methods keep prompts in token space and use gradients to choose better words. HotFlip \citep{ebrahimi2018hotflip} flips individual tokens by approximating the effect on the loss with gradients, and \citet{shin2020autoprompt} pick candidate tokens using gradient signals. \citet{wen2023hard} smooth the search with continuous helpers and then project back to tokens. Work on adversarial suffixes like \citet{zou2023universal} and faster sampling \citep{zhao2024accelerating} shows that gradient-guided discrete search works well for finding strong suffixes when we have white-box access.

% Idea: continuous prompt optimization and projection
\paragraph{Continuous optimization.} Soft prompt tuning replaces hard tokens with learned embedding vectors that we train using backpropagation \citep{lester2021power}. Later work looks at safety and robustness in embedding space \citep{schwinn2024soft}. More recently, \citet{wang2025dpro} study direct prompt optimization with continuous representations; they use stronger objectives to close the gap between soft prompts and discrete use.

% Idea: prompt compression for efficiency
\paragraph{Prompt compression.} To reduce inference cost, coarse-to-fine pruning methods compress demonstrations and questions using perplexity signals from a smaller LM, as in LLMLingua \citep{jiang2023llmlingua} and its distilled version \citep{pan2024llmlingua2}. Gist tokens \citep{mu2023gist} learn short continuous summaries, and context-aware compression uses sentence encodings \citep{liskavets2024prompt}. TACO-RL \citep{shandilya2024taco} adds task-aware rewards to compression to keep outputs accurate when length is limited.

% Idea: reinforcement learning for prompt editing and safety
\paragraph{Reinforcement learning.} RL has been used to optimize prompts or policies that choose edits over sequences \citep{ramamurthy2022rlnlp}, and to align or steer LMs with discrete action spaces. Our work connects to this line by treating length control as a policy that decides when to compress or improve likelihood, instead of just tuning embeddings.

\section{Problem Formulation}
\label{sec:problem}

\begin{figure*}
    \centering
    \includegraphics[width=0.95\linewidth]{figures/gcg_length_sweep.pdf}
    \label{fig:gcg_length_sweep}
    \caption{\textbf{GCG optimizes for likelihood, not for length.} We run GCG with suffix lengths from 1 to 32 tokens on a single AdvBench prompt and plot the final log-likelihood (y-axis in log scale). The landscape is somewhat chaotic, which is why we show only one prompt; averaging multiple prompts would smooth out this noise and hide the true optimization challenge. As length grows GCG improves likelihood but never tries to compress. An RL agent needs to navigate this chaotic landscape to find points with good enough likelihood using much shorter suffixes.}
\end{figure*}

Standard prompt optimization methods treat length as fixed. Figure~\ref{fig:gcg_length_sweep} shows the limitation: when we run GCG with suffix lengths from 1 to 32 tokens, we see that longer suffixes get better likelihood, but the optimizer never tries to reduce length. The landscape is also chaotic, with no smooth relationship between length and performance. This means we need a method that can navigate this rough terrain to find suffixes with good-enough likelihood at much shorter lengths.

More formally, we want to find a suffix \(s\) that makes a frozen LM \(p_\theta\) give high probability to a fixed target completion while keeping \(s\) short. We use \(x\) for the fixed prefix (e.g., a harmful user query), \(y\) for the fixed target completion (e.g., the harmful response), and \(s\) for the suffix we optimize. The full input to the model is the concatenation \(x + s\), and we want the model to assign high probability to \(y\) given this input. The optimization problem is:
\begin{equation}
  \min_{s} \mathcal{L}(s) = -\log p(y \mid x, s),
\end{equation}
with a preference for small \(|s|\) (the suffix length). We don't update the model parameters \(\theta\); all edits act on \(s\). Each edit either changes the suffix length (by adding or removing a token) or replaces suffix tokens in place.

We set this up as a finite-horizon Markov decision process (MDP). A state \(z\) contains the current suffix length and likelihood statistics (like log-likelihood and length ratios). Actions only affect the suffix; they either call the content optimizer or change the length. The reward tries to balance two things: making \(y\) more likely and keeping the suffix short.

\subsection{State Space}
\label{subsec:state}

We maintain a compact, five-dimensional state per rollout that summarizes suffix size, model fit, and episode progress:
\begin{enumerate}[itemsep=0pt, topsep=2pt]
  \item normalized length \(|s|/|s_0|\), where \(|s_0|\) is the initial suffix length at the start of the episode;
  \item current length \(|s|\);
  \item current log-likelihood \(\ell = \log p_\theta(y \mid x_{\text{pref}}, s)\);
  \item likelihood ratio \(\ell / (\ell_0+\varepsilon)\), where \(\ell_0\) is the log-likelihood at the episode start and \(\varepsilon\) is a small positive constant for numerical stability;
  \item episode progress \(t/T\), with \(t\) the current step and \(T\) the episode length.
\end{enumerate}
These statistics are inexpensive to compute and keep the policy lightweight.


\subsection{Action Space}
\label{subsec:actions}

Actions operate solely on the suffix \(s\): \(\{\text{optimize}, \text{shrink}, \text{grow}\}\). \emph{Optimize} runs the inner optimizer (Section~\ref{subsec:modes}) on the current suffix content without changing its length. \emph{Shrink} removes the last active suffix token (if \(|s|>0\)). \emph{Grow} adds one suffix token up to \(L_{\max}\); the new slot is initialized by the optimizer (a random non-special token in discrete mode, a BOS embedding in continuous mode). The prefix and target completion remain fixed throughout.

\subsection{Reward Function}
\label{subsec:reward}

At each step we compute an immediate reward that balances likelihood and suffix length as follows:
\begin{equation}
  r_t \;=\; \alpha\,\tilde{\ell}_t \;-\; \beta\,\frac{|s_t|}{L_{\max}},
\end{equation}
where \(\tilde{\ell}_t\) is the per-token log-likelihood of the target completion \(y\) under the current suffix and \(|s_t|/L_{\max}\) is the normalized suffix length. Returns are the discounted sum of these step rewards,
\begin{equation}
  R_t \;=\; \sum_{k=t}^{T-1} \gamma^{\,k-t}\, r_k,\quad t = 0,\dots,T-1,
\end{equation}
so earlier actions receive credit proportional to their contribution over the remainder of the episode. Returns are centered per prompt group to form advantages for the GRPO update. This step-based formulation provides immediate feedback on both likelihood and length at every decision point.


\section{Methods}
\label{sec:method}

% Idea: describe pipeline from inputs to policy and inner optimizers
We pair a frozen LM with a small policy network. The policy decides when to shrink, grow, or call an inner optimizer; the inner optimizer improves the suffix tokens or embeddings. We train the policy with Group Relative Policy Optimization (GRPO) \citep{shao2024deepseekmath} while leaving the LM untouched.

\subsection{Policy Network Architecture}
\label{subsec:policy}

% Idea: lightweight MLP with epsilon-greedy sampling
The policy is a two-layer MLP that maps the five state features to three action logits. We apply a temperature, softmax, and epsilon-greedy mixing to sample actions. We include an entropy bonus and clip ratios as in GRPO to keep updates stable. Exploration rate $\epsilon$ decays each episode; gradients only update the policy parameters.

\subsection{Optimization Modes}
\label{subsec:modes}

% Idea: plug-in inner optimizers for different search spaces
We support three plug-in inner optimizers; the policy is agnostic to which one is used.

\subsubsection{Continuous Optimization}
\label{subsubsec:continuous}

% Idea: optimize suffix embeddings directly
In continuous mode we work directly with suffix embeddings instead of tokens. The suffix is a trainable block of shape $[B, L_{\max}, D]$ where active slots start with the BOS embedding. Adam \citep{kingma2014adam} updates these embeddings to increase the log-likelihood of the target completion, while prefix and completion embeddings stay frozen. Length changes happen through the attention mask: when we grow the suffix we activate one more slot (which gets initialized on the next update), and when we shrink it we deactivate the last slot. At the end we project active embeddings to their nearest vocabulary tokens by L2 distance for reporting.

\subsubsection{Continuous with Projection}
\label{subsubsec:continuous_proj}

% Idea: add distance regularization to stay near the embedding table
This optimization mode extends the continuous approach by encouraging suffix embeddings to stay near real tokens during training. For each active position we compute its distance to the vocabulary and add this distance as a penalty in the loss. The full objective is:
\begin{equation}
  \mathcal{L}_{\text{total}} = -\log p(y\mid x,s) + w_{\text{proj}}\,\mathcal{L}_{\text{proj}}
  \label{eq:continuous_proj_loss}
\end{equation}
where $w_{\text{proj}}$ is the projection weight and $\mathcal{L}_{\text{proj}}$ is the mean distance from active suffix embeddings to their nearest vocabulary tokens. In our experiments we use L2 distance for this metric. During evaluation we project suffix embeddings to tokens before computing the reward, which ensures the policy sees scores that match discrete prompts. This also lets us track the average projection distance to see how deployable the learned embeddings are.

\subsection{Training Procedure}
\label{subsec:training}

We run batched, fixed-horizon episodes with multiple rollouts per prompt. For each batch we build inputs, roll out \(T\) steps, and collect states, actions, and log-probs. After each episode, compute the terminal reward, discount it backward, center advantages per prompt (GRPO), and run several GRPO epochs with clipping and entropy bonus.

\subsection{Implementation Details}
\label{subsec:implementation}

We construct a fixed batched layout with three segments per example: an immutable prefix, a trainable suffix, and an immutable completion. Prefixes are left-padded and completions right-padded with their own attention masks. The suffix is a trainable buffer of shape \([B, L_{\max}]\) (tokens in discrete mode, embeddings in continuous mode) with an attention mask marking active positions; the first \texttt{init\_len} slots are active at initialization. Length edits toggle this mask: \textit{grow} activates the next inactive slot, \textit{shrink} deactivates the last active slot. Newly activated slots are initialized by the optimizer when the suffix is updated.

For forward passes, the three segments are concatenated and a combined attention mask is built; suffix start indices are tracked so discrete optimizers can splice candidate suffixes efficiently. In continuous modes, concatenated embeddings are provided; in discrete mode, concatenated token IDs are used. Edits and gradients are confined to the suffix; prefix and completion remain fixed. All experiments use a frozen Pythia-70M backbone.

\subsection{Additional Experiments and Insights}

Beyond the core results reported in Section 5 \ref{sec:experiments}, we conducted a series of exploratory experiments to better understand the behavior of different policy objectives, reward scalings, and state representations. While these results are not included in the main paper due to space and time constraints, we summarize the most relevant observations here to document the full extent of our experimental efforts.

\paragraph{Alternative RL Algorithms.}
We implemented both REINFORCE \citep{williams1992reinforce} and PPO \citep{schulman2017ppo} as drop-in replacements for GRPO. REINFORCE was generally stable but showed slower convergence. PPO required training a separate value network, and we repeatedly encountered exploding value losses before stabilization. Once tuned, PPO matched (but did not exceed) GRPO performance, so we ultimately focused on GRPO for the final results.

\paragraph{State Representation Variants.}
Early experiments revealed a separate issue: we had included a layer normalization step inside the state encoder, which unintentionally collapsed several state features to be nearly identical values. This caused the policy to output a grow probability of almost 1.0 for many states, leading to uncontrolled suffix expansion at the beginning of each episode. Removing the layer norm and introducing $\epsilon$-greedy exploration mitigated this collapse and restored healthy action diversity. We also experimented with richer representations, including hidden-state vectors extracted from the frozen LM (corresponding to suffix tokens) and a deeper policy network with roughly 500K parameters. Ultimately, the richer state representations did not outperform the simpler five-dimensional state described in Section~\ref{subsec:state}, so we retained the computationally efficient variant.

\paragraph{Action Imbalance Issues.}
Early in development, the policy collapsed to always selecting \emph{grow}, causing the suffix length to increase rapidly at the start of each episode. This led to poor reward signals and hindered learning. We resolved the imbalance by normalizing length-based rewards, tuning $\beta$, and adjusting entropy and exploration schedules.

\paragraph{Reward Scaling.}
Although PPO and GRPO are theoretically scale-invariant, in practice the policy failed to learn when rewards used raw log-likelihoods and raw lengths. Reward magnitudes differed by several orders of magnitude, saturating the advantage estimates. Normalizing both likelihood and length terms significantly improved learning stability and accelerated convergence.

\paragraph{Summary.}
Overall, these exploratory experiments helped shape the final method even though they are not directly reflected in the main results. They also highlight practical considerations when applying RL to prompt optimization—particularly the importance of reward normalization, balanced action distributions, and avoiding unnecessarily complex state encodings.

\subsection{Limitations}

% Idea: acknowledge scope and potential issues
As with any work, we have our limitations, and for scientific rigor we want to be transparent about them. We only test on a small LM (\texttt{Pythia-70M}), so results might be different with larger models. The policy is trained for a fixed maximum suffix length, which makes it less flexible. We also assume white-box access to the LM for gradient computation; this is not always possible in practice. Our experiments focus on adversarial prompt discovery instead of general prompt optimization tasks. Finally, the policy might not work well across different domains or model families without retraining.

\subsection{Future Work}
\label{subsec:future}

One direction for future work is to try richer state and policy representations. Our five-dimensional state works well enough for this study, but we could add gradient or attention features, or use hidden-state summaries from the frozen LM; this might help with credit assignment. Deeper policy networks could also work if we pair them with better normalization.

Another direction is to design more expressive editing actions. Right now our action space is limited to coarse operations like shrink, grow, and optimize; these treat the suffix as a single block. We could extend this to let the policy pick a specific position in the suffix and do a targeted insertion, deletion, or replacement. Such fine-grained actions (maybe guided by saliency maps, gradient signals, or likelihood sensitivities) would give us more control over how suffixes change and let us manipulate prompt structure more precisely.

We could also revisit the reward formulation. Different scaling strategies, extra reward terms (like smoothness or stability penalties), or even learned reward models might give better trade-offs between likelihood and brevity.

A related direction is to use stronger inner-loop optimizers. Recent work on accelerating greedy coordinate methods, like probe-sampling variants of GCG \cite{zhao2024accelerating}, could be more efficient than the standard coordinate search we use here. Another option is to replace GCG with RL-based discrete optimization frameworks like RLPrompt \cite{deng2022rlpromptoptimizingdiscretetext}, which learn token-level replacement policies end-to-end. As far as we know, no one has tried to combine such discrete replacement strategies with explicit, RL-driven length-editing actions. So jointly optimizing both content and the structural length of prompts is still an open area.

Finally, scaling and safety are important challenges. If we want to use these methods with larger LMs, real-world settings, or high-stakes domains (e.g., jailbreak prevention), we'll need extra guardrails, better evaluation metrics, and careful thinking about dual-use risks.

\section*{Ethical Considerations}

% Idea: discuss dual-use and responsible research
Our work focuses on prompt optimization techniques that can be used for both good and bad purposes. We frame our experiments using adversarial suffix generation (a common setting in the literature), but we know that these methods could be misused to create harmful content. Our goal is to better understand prompt optimization and length trade-offs, not to help malicious uses. Researchers who use these techniques should think about the ethical implications and add proper safeguards. We release our code expecting it will be used responsibly for research that helps the community.
